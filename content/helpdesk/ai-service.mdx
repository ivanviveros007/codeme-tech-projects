# AI Service

The AI Service is the intelligence layer of the Helpdesk system. It receives a support ticket, runs it through an AI pipeline (embedding → RAG → LangGraph agent → decision), and returns a structured JSON telling the backend which technician should handle it, at what priority, and why.

## Pipeline overview

Every ticket goes through 6 stages before a decision is returned:

<MermaidDiagram
  chart={`flowchart LR
    A[POST /analyze] --> B[Text cleaning]
    B --> C[Embedding\nGemini]
    C --> D[RAG search\nChromaDB]
    D --> E[LangGraph\nReAct agent]
    E --> F[get_routing_context tool\nBackend API]
    F --> E
    E --> G[JSON decision]
    G --> H[Store in\nChromaDB]`}
  caption="Full pipeline: from HTTP request to structured decision"
/>

### Stage 1 — Text cleaning
File: `app/utils/text_cleaner.py`

The raw ticket text is normalized before embedding:
- Unicode normalization (NFKC)
- Control characters stripped
- Truncated to 4,000 characters to stay within model limits

### Stage 2 — Embedding
Using `models/text-embedding-004` from Google Generative AI. The cleaned text is converted to a vector that captures semantic meaning. This vector is used for RAG search.

### Stage 3 — RAG (Retrieval-Augmented Generation)
ChromaDB is queried for the 3 most similar historical tickets (cosine similarity threshold: 0.75). If similar resolved tickets are found, their resolution summaries are injected into the agent's context. This helps the agent make better decisions based on past experience.

### Stage 4 — LangGraph ReAct agent

This is the core of the service. A ReAct (Reason + Act) agent loop:

<MermaidDiagram
  chart={`sequenceDiagram
    participant A as Agent
    participant T as get_routing_context tool
    participant B as Backend API

    A->>A: Read ticket + RAG context
    A->>T: Call tool (reason: need technicians)
    T->>B: GET /api/internal/routing-context?org_id=xxx
    B-->>T: { org_context, niveles, tecnicos }
    T-->>A: Routing context returned
    A->>A: Reason: match skills, evaluate priority
    A->>A: Output JSON decision`}
  caption="LangGraph ReAct loop: the agent calls the routing tool once, then produces the final JSON"
/>

### Stage 5 — Routing context tool

The tool calls the backend's internal endpoint with the `org_id` of the ticket. It returns:

```json
{
  "org_context": {
    "company_type": "it_services",
    "ai_custom_instructions": "ABAP dumps in production = priority 10..."
  },
  "niveles": [
    { "numero_nivel": 1, "max_complexity_score": 4, "tags": ["consulta_uso", "authorization"] },
    { "numero_nivel": 2, "max_complexity_score": 8, "tags": ["abap", "performance"] }
  ],
  "tecnicos": [
    { "id": "uuid", "nombre": "Ana R.", "skills": ["abap", "sap_basis"], "carga_actual": 2, "nivel": { "numero": 2 } }
  ]
}
```

<Callout type="info">
  **Multi-tenancy**: The `org_id` is passed via a Python `ContextVar` — not as a tool argument. This keeps the LangGraph tool signature simple while still filtering all data per organization. The `ContextVar` is set in `run_agent()` before invoking the agent and reset in the `finally` block.
</Callout>

### Stage 6 — Prompt construction

The system prompt is built dynamically based on `org_context`:

```python
# app/agent/prompts.py
def build_system_prompt(company_type, custom_instructions):
    prompt = BASE_SYSTEM_PROMPT
    if company_type and COMPANY_TYPE_CONTEXTS.get(company_type):
        prompt += f"\n\n## Company Profile\n{COMPANY_TYPE_CONTEXTS[company_type]}"
    if custom_instructions:
        prompt += f"\n\n## Client Instructions (max priority)\n{custom_instructions}"
    return prompt
```

`COMPANY_TYPE_CONTEXTS` has pre-written sector profiles for: `tech_saas`, `ecommerce`, `healthcare`, `retail`, `it_services`. The `ai_custom_instructions` from the org always override everything else.

## Decision output

The agent must return a strict JSON (no markdown, no extra text):

```json
{
  "ticket_id": "uuid",
  "category": "abap_dump",
  "priority": 9,
  "complexity_score": 8,
  "suggested_level": 2,
  "assigned_tecnico_id": "uuid-or-null",
  "reasoning": "Production ABAP dump in VL02N. Highest priority per client rules. Ana R. selected: abap skill match, level 2 clearance, lowest load (2 active tickets vs 5 for next candidate).",
  "similar_tickets": [
    { "ticket_id": "uuid", "similarity_score": 0.89, "resolution_summary": "..." }
  ]
}
```

<Callout type="warn">
  If the LLM returns the JSON wrapped in markdown code fences, `_extract_json()` in `app/agent/agent.py` strips them with a regex. This handles model inconsistency gracefully.
</Callout>

## How to run locally

```bash
cd helpdesk-ai-service
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # fill in GEMINI_API_KEY
uvicorn app.main:app --reload --port 8000
```

The service starts at `http://localhost:8000`. Swagger docs available at `/docs`.

<Callout type="tip">
  ChromaDB persists its vector store to `./chroma_data/` by default. If you reset the database and want a clean RAG state, delete this folder before restarting the service.
</Callout>
