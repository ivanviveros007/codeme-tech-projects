# Landing Page

The Landing Page is the public marketing site for Helpdesk. It communicates the product's value proposition — AI-powered, skill-based ticket routing — to potential clients. It supports English and Spanish via `next-intl`, uses a dark zinc-950 design, and ends with a beta signup form backed by a Resend API call.

## Section architecture

The page is split into 6 sections, each a standalone server component under `components/sections/`. The root page at `app/[locale]/page.tsx` composes them in order.

```
Landing
├── Navbar              — dark header, logo, CTA button, locale switcher
├── Hero                — dot-grid background, headline, browser mockup with live stats
├── Problem             — before/after panels showing manual vs AI routing
├── HowItWorks          — 3-step process with monospace AI output box
├── Features            — 2×2 dark cards with numbered items and code snippets
├── ForWho              — 3 industry cards (SaaS, IT services, e-commerce)
├── BetaForm            — email input → Resend API → confirmation
└── Footer              — minimal 3-column horizontal
```

## Internationalization

`next-intl` handles routing at the locale segment level. All copy lives in `messages/en.ts` and `messages/es.ts`. Components use `useTranslations()` and reference typed keys — missing keys cause a TypeScript error.

```typescript
// components/sections/Hero.tsx
const t = useTranslations("hero");

<h1>{t("headline")} <span className="text-indigo-400">{t("headlineAccent")}</span></h1>
```

**Message structure** (abridged):

```typescript
// messages/en.ts
export default {
  nav:        { brand, links, cta },
  hero:       { eyebrow, headline, headlineAccent, sub, cta, mockStats[], mockTickets[], mockReasoning },
  problem:    { eyebrow, headline, sub, before: { label, steps[] }, after: { label, steps[] }, stat, statLabel },
  howItWorks: { eyebrow, headline, steps[], aiExample: { label, fields[], reasoning } },
  features:   { eyebrow, headline, items[{ number, title, description, example }] },
  forWho:     { eyebrow, headline, items[{ industry, scenario, value, example }] },
  betaForm:   { eyebrow, headline, sub, placeholder, cta, benefits[], successTitle, successSub },
}
```

The Spanish translation in `messages/es.ts` mirrors this structure exactly.

## Hero mockup

The Hero section renders a fake browser window (dark zinc-900 with three dots) that shows a live-looking support dashboard: two stat cards (`ticketsHoy`, `tiempoPromedio`), a list of 3 mock tickets with priority badges and "hot" indicators, and a monospace AI reasoning box.

All mock data comes from translations — nothing is hardcoded in the component:


## Beta form

The form submits to `POST /api/beta-signup`, a Next.js route handler that uses the Resend SDK to send a notification email to the owner.

```typescript
// app/api/beta-signup/route.ts (pattern)
export async function POST(req: Request) {
  const { email } = await req.json();
  await resend.emails.send({
    from: "Helpdesk Beta <noreply@yourdomain.com>",
    to: process.env.OWNER_EMAIL!,
    subject: `New beta signup: ${email}`,
    text: `${email} signed up for the beta.`,
  });
  return Response.json({ ok: true });
}
```

On success the form replaces itself with a confirmation message using local React state — no page navigation.

## How to run locally

```bash
cd helpdesk-landing
npm install
cp .env.local.example .env.local   # optional — beta form works without Resend in dev
npm run dev
```

The site starts at `http://localhost:3000`. Navigate to `/es` for the Spanish version. The beta form will log to console if `RESEND_API_KEY` is not set.

<Callout type="tip">
  To add a new language: create `messages/[locale].ts` matching the en.ts structure, add the locale to the next-intl config, and the middleware will handle routing automatically.
</Callout>
